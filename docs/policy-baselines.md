# Policy baseline summaries

The source set contains policy drafts and technical hardening notes. This public summary presents the intended governance topics, not approved or enforced policy. A real organization must assign an owner, scope, approval authority, review interval, exceptions process and evidence source before adoption.

| Policy area | Minimum decision points | Evidence to retain |
|---|---|---|
| Acceptable use | Authorized use, prohibited activity, reporting obligations, monitoring notice | Approved policy, acknowledgement record |
| Access control | Joiner/mover/leaver, MFA, role design, privileged access, access reviews, emergency access | Access requests, approvals, review results, exceptions |
| Data classification | Data classes, handling, encryption, transfer, retention and disposal | Classification inventory, handling decisions, disposal records |
| Incident response | Severity, roles, escalation, evidence preservation, communications, recovery | Exercise records, incident timeline and lessons learned |
| Authentication | MFA, credential storage, reset, lockout and service-account handling | Configuration exports, exception register, test outputs |
| System baseline | Supported configurations, patch/vulnerability handling, logging and change control | Baseline versions, change approvals, scan/remediation records |
| Supplier security | Criticality tiers, pre-contract review, minimum security clauses, monitoring and exit | Supplier inventory, due-diligence packet, decision and reassessment logs |

Passwords and numeric thresholds in the source drafts should be reviewed against current enterprise identity standards and threat model before use; they are not reproduced as universal recommendations here.
